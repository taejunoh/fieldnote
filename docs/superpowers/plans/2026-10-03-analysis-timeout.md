# Analysis timeout and interruption audit

## Contract

- `OPENLLMS_UPSTREAM_TIMEOUT_SECONDS` is shared by gateway and worker, defaults to `2700`, and accepts integers from `60` through `3600`.
- The worker's Undici header and body timeouts use the configured value plus 60 seconds. Worker startup validates the setting before creating jobs.
- A partial or interrupted upstream response stays interrupted and is never finalized. The worker stores only allowlisted terminal status, known error code, bounded response ID, HTTP status, fixed transport error kind, cancellation boolean, bounded elapsed-time/event counters, protocol enum, validated request ID, and upstream transport enum (`http` or `ws`) under `llms.terminal`.
- Completed verified responses and ordinary source-free conversation keep their existing finalization paths. No automatic provider replay is added.
